# FRAUDDETECT

FRAUDDETECT is a fraud-monitoring demo with a FastAPI inference service,
PostgreSQL persistence, a JWT-secured React dashboard, and a synthetic-data ML
pipeline. The Compose stack contains exactly three services: backend, Nginx
frontend, and PostgreSQL.

## Run the full stack with Docker Compose

Prerequisites: Docker Desktop (or Docker Engine with the Compose plugin).

1. Copy the example environment file and replace every `REPLACE_WITH_...`
   value with unique secrets. Generate URL-safe values for the database
   password, JWT signing key, and API key:

   ```powershell
   Copy-Item .env.example .env
   python -c "import secrets; print(secrets.token_urlsafe(32))"
   ```

   The JWT key must be at least 32 characters, the API key at least 24
   characters, and the admin password at least 12 characters. Keep `.env`
   private; it is excluded from Docker build context and version control.

2. Build the backend and frontend images and start all services:

   ```powershell
   docker compose up --build
   ```

   The backend waits for PostgreSQL, creates/updates its tables, and seeds the
   configured admin account if one does not exist. The first image build trains
   the demo model and packages its training reference data.

3. Visit `http://localhost:8080` and sign in using
   `FRAUDDETECT_ADMIN_USERNAME` and `FRAUDDETECT_ADMIN_PASSWORD` from `.env`.
   The API and database are not published directly to the host; Nginx proxies
   API and WebSocket traffic over the private Compose bridge network. The
   frontend port is bound to `127.0.0.1` by default. Set
   `FRAUDDETECT_BIND_ADDRESS=0.0.0.0` only when an external ingress or firewall
   is configured.

4. To stop the services while retaining PostgreSQL data:

   ```powershell
   docker compose down
   ```

   `docker compose down -v` deletes the persistent database volume; only use it
   when intentionally discarding the stored data.

The Compose file constructs a PostgreSQL connection URL from the database
environment variables. If setting `DATABASE_URL` yourself, use a
`postgresql+psycopg://user:password@db:5432/frauddect` URL and percent-encode
reserved characters in the password.

The backend runs as a non-root user and retries transient PostgreSQL connection
failures before creating/updating tables. Postgres is not host-published and
the frontend port binds to localhost by default; terminate TLS at a trusted
ingress/reverse proxy before exposing the service publicly.

## Drift monitoring

Run the drift job against the most recent 24-hour inference batch:

```powershell
docker compose exec backend python monitor_drift.py
docker compose cp backend:/app/drift_report.json .\drift_report.json
```

The report uses two-sample Kolmogorov-Smirnov tests for numeric features and
chi-square/Cramer's V tests for categorical features. A detected distribution
shift sets `retrain_recommended` and exits with status 2; fewer than 200 recent
transactions produces an `insufficient_production_samples` report. Adjust the
window and minimum sample size for development:

```powershell
docker compose exec backend python monitor_drift.py --window-hours 72 --minimum-samples 50
```

Feature-distribution checks detect **data drift**. Concept/performance drift is
evaluated only when at least 100 transactions have an adjudicated
`actual_is_fraud` value, populated by a trusted chargeback or fraud-review
process. Without those labels, the report marks concept drift as unavailable;
prediction scores and analyst actions alone are not ground truth.

The training reference CSV and selected model threshold are generated by
`ml_pipeline.py`. To retrain outside the container:

```powershell
python -m pip install -r requirements.txt
python ml_pipeline.py
```

Rebuild the backend image after replacing the model artifact/reference dataset.

## Verification

```powershell
docker compose config --quiet
python -m compileall -q ml_pipeline.py main.py models.py monitor_drift.py
python -m unittest discover -s tests -v
python ml_pipeline.py
npm.cmd --prefix frontend run build
```

These are synthetic-data demo metrics, not evidence of production fraud
performance. Validate drift limits and decision thresholds with representative,
consented, labeled production data before operational use.

## Local development (SQLite)

Use Python 3.11+ and Node.js. The local database remains separate from the
PostgreSQL Compose volume. In PowerShell, configure fresh local secrets before
starting the API:

```powershell
$env:DATABASE_URL = "sqlite:///./fraud_local.db"
$env:FRAUDDETECT_JWT_SECRET = (python -c "import secrets; print(secrets.token_urlsafe(48))").Trim()
$env:FRAUDDETECT_API_KEY = (python -c "import secrets; print(secrets.token_urlsafe(32))").Trim()
$env:FRAUDDETECT_ADMIN_USERNAME = "admin"
$env:FRAUDDETECT_ADMIN_PASSWORD = "ReplaceWithYourOwnStrongPassword!"
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

In another terminal:

```powershell
npm.cmd --prefix frontend run dev -- --host 127.0.0.1
```

Open `http://127.0.0.1:5173`. Existing local admin credentials are not reset
when the database already contains that username; public registration creates
analyst-only accounts. Change the example password before using the demo.

The browser's **Analyze Transaction** page uses the authenticated
`POST /api/transactions/analyze` route, so the ingestion API key is never
bundled into frontend assets. Server-to-server ingestion uses
`POST /api/transactions/evaluate` with `X-API-Key`. Logout invalidates the
current user's tokens server-side. The database stores transaction records,
fraud predictions, alerts, user activity, security logs, incidents,
investigation history, and executed test results.

## Project demonstration video

After signing in, select **Watch Demo Video** on the Dashboard. The project
walkthrough page includes a responsive MP4 player and a feature overview.
Playback controls are provided by the browser; the project does not generate
or include demo footage.

The automated Playwright generator starts a temporary local copy of the actual
application, records the dashboard with visual chapter captions and
transitions, then writes the MP4 at:

```text
frontend/public/demo/frauddetect_demo.mp4
```

To generate it, run:

```powershell
npm.cmd --prefix frontend run demo:video
```

The generator uses a temporary SQLite database and random short-lived
credentials, so it does not need your account and does not add demo records to
your project database. It stops its temporary FastAPI and Vite services and
removes the temporary database after recording. It uses safe
`DEMO-VIDEO-*` transactions and a demo incident. The generated clip is
captured from the actual application and is not fabricated footage.
**Back to Dashboard** returns to the overview; **Explore Live Project** opens
transaction analysis.

The demo page uses native browser controls and serves the generated MP4 from
`frontend/public/demo/frauddetect_demo.mp4`. The designed poster remains as a
preload/fallback image.

## Workflows and reports

- Transaction history supports search, status/risk filters, sorting, date
  windows, and pagination.
- Alerts support severity/date/search filters, investigation notes, status
  updates, and history. Block/resolve actions require an administrator.
- Analytics are calculated from stored transactions and alerts. Model holdout
  metrics are labeled synthetic; production metrics are shown only when
  adjudicated outcomes have been recorded.
- Incident response tracks triage, containment, evidence preservation,
  recovery, resolution, analyst notes, and lessons learned.
- The Security Testing page runs read-only database, validation, model,
  anomaly-detector, and role-gate checks; results are persisted.
- Reports export transaction, fraud, monitoring, incident, model, and test
  records as CSV. Use the browser print dialog for PDF output.
- The application does not scan networks or capture traffic.
